# Deck QA Checklist

Use this after the storyline and slide draft are complete.

## 1. Storyline QA

Read only the slide titles.

Can a judge reconstruct:
- the problem,
- the insight,
- the recommendation,
- why it works,
- why it is feasible,
- what value it creates,
- what decision is requested?

If not, rewrite titles before editing body content.

## 2. One-slide-one-job test

For every slide write:
"This slide exists to prove ______."

If the blank requires "and", the slide may be doing too much.

## 3. Evidence QA

For every number ask:
- source?
- denominator?
- period?
- unit?
- case fact or assumption?
- consistent elsewhere in the deck?

Cross-check all repeated numbers.

Common failure:
an executive-summary number differs from an appendix calculation.

## 4. Mechanism QA

For each solution slide verify:
- target user,
- trigger,
- workflow,
- behavioral mechanism,
- owner,
- feedback loop,
- KPI,
- guardrail.

A branded box without these is not a mechanism.

## 5. Economics QA

Check:
- arithmetic,
- units,
- lakh/crore/million conversions,
- annual vs one-time costs,
- gross vs net benefit,
- adoption assumptions,
- effect-size assumptions,
- double counting,
- scenario labels,
- break-even.

If ROI uses an assumption, show it.

## 6. Implementation QA

Check:
- who owns each phase,
- when value begins,
- dependencies,
- capacity constraints,
- data readiness,
- manager burden,
- employee burden,
- governance,
- scale gate,
- kill/redesign condition.

## 7. Visual QA

Check:
- body text readable at presentation distance,
- title is largest message,
- critical number is visually obvious,
- color is semantic,
- elements align to a grid,
- repeated components look identical,
- no decorative chart junk,
- legends are unnecessary where direct labels work,
- sources are legible.

## 8. Density QA

If a slide has:
- more than 6 major boxes,
- multiple paragraphs,
- several unrelated charts,
- more than one major conclusion,

split or simplify it.

Dense can be acceptable.
Unprioritized is not.

## 9. Judge-readability test

Give each slide 20 seconds.

A judge should understand:
1. what happened,
2. why it matters,
3. what to remember.

If any requires narration to decode, improve the slide.

## 10. Final consistency sweep

Check:
- company name,
- solution name,
- capitalization,
- metric definitions,
- phase names,
- color meaning,
- dates,
- timeline,
- slide numbering,
- appendix references,
- citations,
- currency.

Treat consistency errors as credibility errors.
